# Анализ проделанной работы

## Общий итог по проекту

Разработан ETL-пайплайн для подготовки данных рекомендательной системы книг. 
Пайплайн обрабатывает сведения о пользовательских сессиях и контенте, 
формирует пять аналитических витрин и сохраняет результат в формате Parquet.

Исследование данных и подготовка пайплайна реализована в `Jupyter Notebook`.
Написан итоговый скрипт ETL-пайплайна `project.py`, запускающийся через `spark-submit`.

## Работа в Jupyter Notebook

Ссылка на github с ноутбуком: https://github.com/Plakhotniuk/practicum_ds/tree/main/big_data/book_recomendations

В ноутбуке выполнены следующие этапы:

1. Настроено подключение Spark к S3-совместимому хранилищу Yandex Cloud.
2. Загружены таблицы с пользовательскими сессиями и описанием контента.
3. Исследованы схемы, пропуски, выбросы и распределения признаков.
4. Выполнена предобработка:
   - преобразование даты;
   - удаление записей с неизвестной длительностью контента;
   - фильтрация аномально длинных сессий и произведений;
   - объединение таблиц по `main_content_id`;
   - корректное преобразование строкового списка жанров в массив;
   - фильтрация по периоду и геолокации.
5. Построены пять витрин:
   - `user_content_mart` — взаимодействие пользователя с конкретным произведением;
   - `user_genre_mart` — пользовательская активность и завершённость по жанрам;
   - `user_mart` — общий профиль и предпочтения пользователя;
   - `content_mart` — популярность и потребление контента;
   - `daily_user_mart` — дневная активность пользователя.
6. Создание всех витрин объединено в общую функцию `build_all_marts`.
7. Получен расширенный план выполнения `user_mart`. Основные затратные операции — `Exchange`, `countDistinct`, оконные сортировки, `explode` и `SortMergeJoin`. В качестве улучшений предложены ранняя фильтрация и проекция колонок, сохранение повторно используемых промежуточных витрин и осторожное применение broadcast-соединений.
8. Реализовано сохранение пяти витрин в S3 по структуре:

   ```text
   s3a://<bucket>/results/S24_project_data/<mart_name>.parquet/
   ```

   После записи проверяется наличие `_SUCCESS` и Parquet-файлов `part-*`.

## Финальный Python-скрипт

В `project.py` логика ноутбука собрана в самостоятельный ETL-скрипт. Он принимает обязательные аргументы:

- `start_date` и `end_date`;
- `geo_id`;
- `columns` для вывода распределений;
- `audition_path` и `content_path`;
- `output_path`.

Скрипт проверяет формат и порядок дат, поддерживает передачу колонок через пробел или запятую, читает локальные и S3A-пути, строит витрины и записывает их в отдельные Parquet-каталоги. Spark master и вычислительные ресурсы не зашиты в код и задаются средствами `spark-submit`. Реквизиты S3 загружаются из переменных окружения.

Пример запуска:

```bash
spark-submit \
  --packages org.apache.hadoop:hadoop-aws:3.3.4 \
  big_data/book_recomendations/project.py \
  --start_date 2024-11-26 \
  --end_date 2025-01-01 \
  --geo_id "Москва, Россия" \
  --columns usage_platform_ru genre \
  --audition_path s3a://s3-ds-source/audition.parquet \
  --content_path s3a://s3-ds-source/content.parquet \
  --output_path s3a://<bucket>/results/S24_project_data
```

## Проверка результата

- Запись и последующая проверка пяти Parquet-каталогов протестированы локально.
- Финальный `project.py` успешно выполнен через настоящий `spark-submit` на тестовых входных Parquet-файлах.
- В результате end-to-end теста созданы все пять каталогов витрин с маркерами `_SUCCESS`.

## Итог

Подготовлен воспроизводимый ETL-пайплайн: исследовательская логика оформлена в ноутбуке, а финальная реализация вынесена в параметризованный SparkSubmit-скрипт. Пайплайн формирует все требуемые витрины, поддерживает работу с S3 и пригоден для пакетного запуска из терминала.
